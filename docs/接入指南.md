# 接入与部署指引

## 1. 接口约定

| 项 | 值 |
|---|---|
| Base URL | `https://www.hunmeng.icu/v1` |
| 鉴权 | `Authorization: Bearer sk-xxxx` |
| 协议 | OpenAI Chat Completions |
| 编码 | UTF-8 |
| 流式 | `"stream": true`（SSE） |

支持的端点：

```
GET  /v1/models
POST /v1/chat/completions
POST /v1/embeddings
```

---

## 2. 最少可运行示例

```bash
export POJIA_API_KEY="sk-你的密钥"

curl -s https://www.hunmeng.icu/v1/chat/completions \
  -H "Authorization: Bearer $POJIA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"pojia-fast","messages":[{"role":"user","content":"hi"}]}'
```

返回 200 且含 `choices[0].message.content` 即接通。

## 3. 客户端配置速查

### Cherry Studio
设置 → 模型服务 → 添加 → **OpenAI** → 
- API 地址：`https://www.hunmeng.icu/v1`
- API 密钥：`sk-...`
- 手动添加模型名：`pojia-pro`、`pojia-fast`、`pojia-coder`、`pojia-writer`

### Chatbox
设置 → 模型提供方 → **OpenAI API 兼容**
- API 域名：`https://www.hunmeng.icu`
- API 路径：`/v1/chat/completions`
- 模型：`pojia-pro`

### NextChat
```bash
BASE_URL=https://www.hunmeng.icu
OPENAI_API_KEY=sk-你的密钥
CUSTOM_MODELS=+pojia-pro,+pojia-fast,+pojia-coder
```

### SillyTavern
API → Chat Completion → **Custom (OpenAI-compatible)**
- 反向代理：`https://www.hunmeng.icu/v1`
- 模型：`pojia-pro`

### LangChain (Python)
```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model="pojia-pro",
    api_key="sk-你的密钥",
    base_url="https://www.hunmeng.icu/v1",
)
print(llm.invoke("说人话。").content)
```

### Dify / FastGPT / OneAPI
作为「OpenAI 兼容」上游添加，模型名手填 `pojia-*`，base 填 `https://www.hunmeng.icu/v1`。

## 4. 常见报错

| 报错 | 原因 | 处理 |
|---|---|---|
| `401 Unauthorized` | Key 错、少 `Bearer `、Key 被删 | 重新生成，注意前缀 |
| `404 model not found` | 模型名写错 / 大小写 | 用 `/v1/models` 拷准确名字 |
| `404 Not Found`（URL 层） | 少写 `/v1` 或重复写 | Base 只写到 `/v1`，SDK 会自动补路径 |
| `429` | 并发/QPS 超套餐 | 进群提额或降并发 |
| 流式中断 | 网络抖动 | 客户端开启重连，或改非流式 |
| `502/503` | 线路切换中 | 重试；持续异常看群公告 |

## 5. 自部署（可选）

不想走中转站、自己有卡：

1. 进群 **1109964876** 取部署脚本与权重指引
2. 显存建议：24G（量化）/ 80G（全精度）
3. 推荐栈：`vLLM` + OpenAI 兼容 server，或 `llama.cpp` + `--api`
4. 启动后把 `base_url` 指向自己的 `http://HOST:PORT/v1` 即可

> 同样的客户端配置，只换 base_url 就能在「中转站」和「自建」之间切换。
